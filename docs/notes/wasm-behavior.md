# WebAssembly behavior (seam)

Moved from the `SLICES.md` backlog on 2026-11-03; the backlog keeps a short pitch.

**WebAssembly behavior.** *Suggested next (2026-11-03, from closing Fighting cow, with the API debt list at seven):* the cow's brain is the first behavior worth sandboxing; it already keeps its state in the engine (memory slots), takes plain data in and gives plain data out (`BrainContext`, `BrainOutput`, `Attack`), and trig goes through `libm`, so a `brain.wit` like `movement.wit` should fit. Sandboxed mod code for block behavior, once a toy has behavior worth sandboxing, such as crystals or liquids. Sleeping blocks and read-old, write-new automata. The first step is done: the WebAssembly movement seam (2026-10-26) runs `base`'s movement controller as a component, so block behavior can follow the same pattern (WIT interface in `api`, guest export macro, `wasm_host` wrapper). *To settle (2026-10-27):* keep entity and block state in the engine, not in the mod, before any behavior keeps state in a mod (see the design doc's "Mod memory"). The movement controller still keeps its timers and charge inside the mod and should move to that pattern. Test whether wasmtime lets the engine drop a mod's freed pages (`madvise` on Linux, `DiscardVirtualMemory` on Windows), driven by an allocator in `api`.

*Done 2026-11-06 (WebAssembly behavior seam, see `docs/done-toys.md`):* the cow brain runs as a component (`brain.wit`, `export_brain!`, `wasm_host::WasmBrain`), and movement controllers keep their state in the engine (`memory` in `MoveContext`/`MoveOutput`, no `spawn`). Still open: block behavior once a toy has some, and giving freed pages back once a mod grows big. WIT gotchas met on the way: wit-bindgen's export macro wants a plain type name (implement the exports in the macro), `from` is a keyword (`%from`), and only one file in the package may have comments before its `package` line.
