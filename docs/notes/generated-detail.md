# Generated detail in looks

Moved from the `SLICES.md` backlog on 2026-11-03; the backlog keeps a short pitch.

**Generated detail in looks.** Added 2026-11-03 at the user's request: every look is one 16³ cube that every block of it shows, so noisy looks like dirt repeat in a 1 m grid. The user's idea: the noise parts of a look are just a function (`data_mods::looks`, `Noise::fill`, a value noise over an integer `hash` of the texel and seed), so run it in the shader on the world texel position instead of looking up a cube. Never repeats, no seams, no texture memory, and the integer hash gives the same bits in WGSL as in Rust. Looks stay data (`noise = { colors, scale, seed }`): the shader has one general noise function, and each look's values reach it in a small table. Considered and dropped: several noise variants per look picked by a hash per boxel (simpler, but still a grid of edges) and one bigger seamless tile (a 4 m repeat still shows across a field). Three steps, each small; 1 and 2 can be one toy if wood grain is wanted right away:
1. *Noise in the shader* for pure noise looks (dirt, stone, gravel, ice). Each chunk passes its cell to the shader as integers, never one big float (the pattern wraps after about 100 million blocks). Views away from the world (hotbar, ghost, item pictures, crafting preview) use a fixed position. Turned looks sample in the block's own turned frame. Tests: the Rust recipe, and the WGSL hash matching the Rust one on a few values; the look is judged in play.
2. *Detail layers on baked looks.* The cube keeps the structure (boards, joints, mortar, rings) and the shader adds generated detail over it. Wood grain: noise stretched along the board, like `grain = { scale = [12, 1, 1], strength = 0.1, seed = 3 }`. Grain must follow each board (with `cross = true` layers alternate X and Y), so the cube's unused alpha channel carries each texel's grain direction (X, Y, up, none) and a board number that offsets the noise per board, so neighbors don't continue each other's grain. The planks recipe knows both already. Baking grain into the cube instead was rejected: crossed boards are a whole block long, so every block would show the same boards and a floor would read as a stamp. The same mechanism gives per-brick speckle, slightly wobbly log rings and ragged grass edges that differ block to block.
3. *Large-scale patch tint*: one more noise layer many meters across (a slightly darker or redder patch of ground), so a big field isn't evenly speckled everywhere.

**Mipmaps and distance filtering** (added 2026-11-05, from Shading, at the user's request; they expected mipmaps in Shading). Looks are read texel-exact (`textureLoad`), so far faces can shimmer and show moiré. Baked looks (bricks, planks) can take ordinary mip levels of the look volumes; looks generated in the shader can't be mipmapped, so their fine noise should fade toward its average color with distance (or with the screen-space size of a texel). Design both together in this toy.

*2026-11-11, from Shadow speed:* both new frame-rate profiles turn MSAA off (it cost ~11 ms at 720p), so distant shimmer shows more; this toy's anti-aliasing matters more now.

*Done (2026-11-11, Generated detail; write-up in `docs/done-toys.md`):* steps 1 and 2 (noise on the world position, wood grain along boards) and the anti-aliasing (face slices with mips, anisotropic reads, noise fading octave by octave). Wood ended as boards of one color plus world grain, not baked rows plus grain. Step 3 (patch tint) is left, now as the backlog's Octave noise and patch tint.

**Octave noise** (2026-11-11, the user: "is there a more perfict way to handle the noise phases, like mesure size in camera and have all scales 16*16, 8*8, 4*4, 2*2*, 1*1"). Noise as octaves at powers of two (1 to 16 texels, and 32 to 256 for patch tint), each recipe giving a weight per octave instead of one blob size. Powers of two keep every lattice exact in integers; shift each octave's lattice by its seed so the 16-texel one doesn't sit on block edges. The shader keeps each octave while its blobs are about 2 pixels or more on screen and fades it below, finest first. The key part is a pre-blended palette per look, made at startup: for a value from the octaves still shown and how much the faded ones would spread it, the average of the colors that spread picks. Up close texels stay crisp single colors; far away they take the right blend, not the middle color or one flat average. Cost: up close more octaves run than today's two (zero-weight octaves cost nothing), far away the big octaves keep running where today's noise is a flat average, so not cheaper; the look is the gain. The fade sliders mostly go away.
